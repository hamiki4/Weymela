# Weymela Android 3.0.2, versionCode 12

This update preserves the existing `com.weymela.app` native shell, branding, Production Firebase project and original upload key. It bundles the verified Production V3 Web image `ghcr.io/hamiki4/weymela-v3-web@sha256:cbd367ef400f909d74b7cec206bc0711ee40c25d3e08f165613991affe7f7b95` from commit `84996141abbf24cb0af39c8858a9e519ecf3678a`. The release plan records this source and the exact owner-confirmed upload certificate fingerprint.

The Android API bridge uses HTTPS `api.weymela.com` and preserves server-owned cookie/device sessions, profile headers and idempotency. It disables redirects, removes cookie response headers before JavaScript and denies general cookie and HTTP bridges. Capacitor is pinned to 8.5.3. Native HTTP policy tests and JavaScript transport tests exercise the bridge; a physical Android acceptance session remains a separate verification step.

CI runs locked tooling installation, dependency audit, transport tests, native release unit tests, SDK 36 compilation and unsigned AAB inspection. Prepare the pinned Web assets with `python3 prepare-assets.py`, provision the existing Production Android public Firebase configuration at ignored `android/app/google-services.json`, then run `npx cap sync android`. From `android`, run `./gradlew --no-daemon testReleaseUnitTest bundleRelease -PweymelaUnsignedValidation=true -PweymelaVersionCode=12`. An unsigned artifact cannot authorize publication.

Before signing, reread Google Play tracks, bundles and APKs and confirm versionCode 12 remains unused. Signing must use the existing `/etc/creatorpay/android-upload/weymela-upload.jks`, original alias `weymela-upload` and protected password file, with its certificate matching the owner-confirmed Play upload certificate. Keep all signing material outside Git and hosted CI. Never generate a replacement key. Signed Gradle builds require `WEYMELA_ANDROID_UPLOAD_KEYSTORE`, `WEYMELA_ANDROID_UPLOAD_PASSWORD_FILE` and `WEYMELA_ANDROID_EXPECTED_UPLOAD_SHA256`; the controlled release process may instead sign the verified CI bundle locally with the same key. Verify the signed bundle with strict jarsigner, bundletool, metadata checks and SHA-256.

The owner manually uploads the signed AAB to the existing Google Play Console application. This workflow does not upload a bundle, commit a Play edit, select a rollout or publish a release. Production software validation does not assert real inbox delivery, bank settlement, TikTok ownership, external payouts or physical-device acceptance.
