# Weymela Android 3.0.3, versionCode 13

This release bundles the verified Production Web image `ghcr.io/hamiki4/weymela-v3-web@sha256:8c20a564b406bac155a7a16016a4eeefebb94a478a5107b0984ac3fb538962e4` from commit `1988382779ae068444b2e0d4a3ef582bb522ab8a`. It includes the preferred receiving-number form, separated promotion funding and concise English/Amharic role guidance. The existing com.weymela.app native shell, branding, SDK 36 target, Production Firebase project and original weymela-upload key remain in use.

The HTTPS API bridge keeps Production cookie/device sessions, profile headers and idempotency. Redirects and general native HTTP/cookie access remain denied. CI checks locked dependencies, nine transport tests, native release policy tests, SDK 36 compilation, Production Firebase resources and unsigned bundle metadata. No physical Android acceptance session is claimed by these tests.

Run `python3 prepare-assets.py`, provision the existing public Production Firebase Android configuration at ignored `android/app/google-services.json`, then run `npx cap sync android`. From android, run `./gradlew --no-daemon testReleaseUnitTest bundleRelease -PweymelaUnsignedValidation=true -PweymelaVersionCode=13`. Signing occurs locally only after protected CI/merge and exact certificate matching against the owner's original upload key. Never generate or reset a key, put signing material in Git/hosted CI, or upload an unsigned bundle.

Play tracks, bundles and APKs were inspected before selecting this code; inspect them again immediately before signing. The owner uploads the final signed AAB manually. This workflow never uploads a bundle, commits a Play edit, chooses a rollout or publishes a release. Live TikTok/provider evidence, settlement/payout execution and new-user email inbox acceptance remain separate from software and packaging validation. Product-specific financial rules are configured by Platform Admin; missing required values are not invented.
